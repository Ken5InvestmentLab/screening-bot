# TV-Free 本番移行準備・判定計画

更新日: 2026-09-13
状態: **NO-GO / 研究限定**
対象: TV-Free Core / Monster の将来移行判断。本書は承認や本番変更の指示ではない。

## 現在の判定

現時点で本番移行しない。Core は登録済み3枠に昇格可能な候補がなく、Monster は探索poolに留まり、登録済みTop-N選出政策は成立していない。V29は比較参考の35件標本であり、TV-Freeの全ユニバース候補でも同一定義のベンチマークでもない。現行Botと同じ対象・時刻・エントリー/決済定義による優位性は確認できていない。Fundamental V2は固定入力再現性の確認に留まり、独立した情報取得とpoint-in-time予測価値は未確認である。

| 移行ゲート | 現状 | 次へ進む条件 |
|---|---|---|
| 昇格対象 | 不成立 | CoreまたはMonsterの固定pool、選出件数/日、ranking、tie-breakが登録ゲートを通過 |

## 移行前の段階ゲート

1. **研究候補の凍結** — family/spec、universe、pool定義、複数銘柄/日のselection policy、入力時点、entry/exit、費用、欠損処理、ランキング、tie-break、データとコードのhashを保存する。候補なし、選出政策未成立、または合格基準未達ならそこでNO-GOを維持する。
2. **データ供給の通常環境確認** — 実際に本番で稼働する予定の非Codexプロセスが使えるデータ元・権限・更新時刻・調整済み/未調整価格の意味・リトライ・レート制限・監査ログを確認する。機能をCodex/LLMに依存させない。認証や利用許諾が不足する場合は人間の解決まで保留する。
3. **データ品質の証明** — 東証営業日/銘柄履歴、上場廃止・コード変更・株式分割等、OHLCVの単位と欠損、時刻、重複を検査する。欠損を推測値で埋めず、対象行を明示的に無効/未解決として記録する。Yahoo等の日足から1時間足・4時間足・シグナル時刻の足を生成してはならない。独立した根拠あるintradayソースを通常環境で利用できない欠損は未解決のまま残す。
4. **比較可能なforward記録** — scorer/policyをfreezeし、各日の日次入力hash・候補全件・選出全件・見送り理由・時刻・出力・成熟後ラベルを追記専用で保存する。すでに結果を見た歴史期間は真のOOSと呼ばない。現行Botとの比較は同一target/entry/exit/費用・同じ成熟期間に揃え、別定義しか存在しない場合は「比較不能」と報告する。CoreとMonsterは異なる役割の指標で評価する。
5. **Codex不要のdry-run** — 外部通知をせず、通常予定ランナーで連続した実行可能日を処理するローカル/隔離環境を使う。入力欠損時の停止/見送り、決定性、複数銘柄/日、ログの秘密除去を確認する。Codex不在で動かせない部分があれば実装・昇格しない。
6. **承認後の段階移行のみ** — 上記の全ゲートをPASSした後に、別途ユーザー承認を得て初めてテスト通知、並行運転、限定公開、本番切替を検討する。本書の作成・dry-run・研究branchのpushは本番承認に当たらない。

## 切戻しと運用安全

本番切替を将来承認された場合も、TradingView系の現行経路を即時削除せず、切替点・担当者・観測期間・復旧方法を事前に書面化する。異常、データ不整合、出力欠落、基準逸脱があればTV-Free経路を停止して既存経路へ戻し、失敗runと入力hashを保存する。secretは環境secret管理に限り、コード・artifact・ログへ出さない。研究段階ではDiscord、Spreadsheet、GAS、Actions、本番watchlist、既存score logicに接続しない。変更を要する段階で改めて承認を得る。

## 次回の再開条件

NO-GOを解除するには、新しい事前登録実験で少なくとも昇格候補と複数銘柄/日を含む固定selection policyが成立し、同一定義で現行Botとの比較可能性が確保され、Codex不要データ実行と完全性監査の証拠が揃う必要がある。現在閲覧済みの研究期間や失敗実験を再利用してOOSを主張しない。新しいCore familyを登録する場合は、失敗済み3枠の小さな閾値調整ではなく、異なる根拠と未閲覧または将来forwardの検証計画を必要とする。Monsterのpool診断は選出政策成立とみなさない。
