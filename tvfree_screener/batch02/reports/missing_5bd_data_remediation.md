# 5BD評価窓の日足欠損 — 検証結果と対策案

更新日: 2026-09-13  
範囲: TV-Free research only。production、Discord、Sheets、workflow、intraday生成は変更していない。

## 結論

公式取引日の5BD評価窓でエントリー日の始値または5営業日目の終値が欠けると、定義済みの5BDリターンを計算できない。中間日だけが欠け、両端の価格が有効なら端点比の算術値は出せるが、現行評価は全5営業日のOHLCVと売買可能性を確認するため、その行は引き続き未解決とする。欠損した足を飛ばして期間を延ばしたり、前値で埋めたりしない。

## 現行コードと保存データの証拠

- batch01/evaluation.py の build_five_session_labels は、全選出に1行を残し、シグナル翌営業日から5営業日目までの全バーを検査する。欠損は MISSING_ENTRY_BAR / MISSING_HOLDING_SESSION_BAR / MISSING_EXIT_BAR として未解決にする。出来高ゼロ・不正OHLCVもリターン計算対象外にし、要求件数から削除しない。
- 既存テスト test_evaluation.py / test_core_moderate_ridge.py は、entry・holding・exit欠損を別状態にするケースを含む。
- 保存済みYahoo由来データはXTKSの市場営業日1,148日をすべて含むが、日ごとの銘柄行数は646〜3,696（中央値3,555）。市場カレンダーが完全でも、個別銘柄の日足が完全とは言えない。point-in-time上場期間・売買停止・無約定を識別する情報はこのCSVにない。
- research downloaderのrun.pyは取得例外・空バッチを再試行する一方、応答全体が非空でも個別tickerの欠損日を期待カレンダーと照合して単独再取得する処理を持たない。欠損が通信失敗と確定したわけではない。
- 今回の凍結CMF選出では1,800件中32件（1.8%）が未解決で、2022H2は8/595、2023は24/1,205。内訳はゼロ出来高の保有日16、entryのゼロ/不明出来高3、canonical label行なし13。canonical label行なしは価格足欠損と同義ではないため、ローカル成果物からラベル生成・結合を再構築できるかを別途監査する。価格足の解決数と評価パイプラインの結合漏れを混ぜない。CMF成績は解決ラベルの成績としてのみ報告した。

## 無料・Codex不要の補完元を再監査した結論

ユーザーは方針を更新し、無料のYahoo Finance日足を補完に使う希望を示した。研究では、すでにローカルに存在するYahoo由来の日足パネルを使ったラベル再構築を実施した。一方、公式条件を再確認するとYahoo!ファイナンスの自動取得と商用利用には制限がある。したがって新たなYahooネットワーク取得コードは加えず、日足ファイルが通常運用で許可された方法によりローカルへ届く前提の、Codex不要なPython側処理と品質検査を設計する。許可された取得経路が確立するまでは、本番へ自動接続しない。

- **Yahoo!ファイナンス**: LINEヤフーの公式ヘルプは、掲載株価のプログラムによる機械取得を禁止し、掲載情報の転用・複製・外部配信・商用利用も禁止している。したがって既存のYahoo由来キャッシュの欠損を同じサイトへ自動で再要求する運用は提案しない。
- **JPX J-Quants API Free**: JPXが公表したFreeプランは0円、日足、過去2年、12週間遅延。ただしJPXの利用者区分ではJ-Quants APIは個人向けで、法人利用・再配布不可。運営中の会員向けBotがその「私的利用」に当たると確認できないので、Botの補完元として採用しない。APIキーとアカウント登録も必要。
- **JPX公開ページ/日報**: 日報は個別銘柄の四本値・売買高を掲載し、バックナンバーは直近12か月。過去株価ページは手動取得を基本とし、自動取得を控えるよう案内し、掲載ファイルの転載を禁止している。JPXサイトの利用条件は、許可や有料契約なしの商用データ収集・二次利用を不可とし、高頻度・高負荷につながる自動取得を控えるよう定めている。無償の公開情報だからといって、会員向けBotで自動収集・再利用できるとは扱わない。
- **J-Quants Pro / DataCube等**: 有料または購入型のため、ユーザーの条件から除外する。

この結果は、データ欠損が解決不能だと証明したものではなく、現在確認できる無料経路を本番用途へ使う権利とCodex不要の自動実行の両方を満たせていない、という判断である。将来、明確に無料で自動利用とBot用途が許諾されたソースが見つかった場合だけ、調整価格・銘柄コード・無約定/停止・全5BDカバレッジを独立検証する。

## Yahoo日足でできる妥協案

すでに保存されているYahoo由来の日足OHLCVは、5BDの評価ラベル再構築に使える。今回、凍結CMF候補の1,800選出について別実験のラベル表に無かった13行を、同じローカル日足パネルから再生成した。13行すべてが `RESOLVED` になり、元からあった1,768解決ラベルのステータス・entry/exit価格・リターンは再生成結果と一致した。選出条件や閾値は変更していない。

この補修後も成績は弱い。0.5%往復コスト仮定で、2022H2は589/595解決、平均-0.954%、中央値-0.856%、勝率32.7%。2023は1,192/1,205解決、平均-0.250%、中央値-0.706%、勝率34.1%。これで解決済みラベルは合計1,781/1,800となり、残る19行（ゼロ出来高16、entryの出来高ゼロ/不明3）は価格が無い事実を勝手に補ってはいけないため未解決のままにする。詳細は `cmf_local_label_coverage_recovery.md` を参照。

1時間足の品質監査では、完了した同一営業日・銘柄について1時間足を日足へ集約し、日足と次を照合する。

- 始値: 最初の有効1時間足の始値
- 高値/安値: 1時間足の最高値/最安値
- 終値: 最後の有効1時間足の終値
- 出来高: 1時間足出来高の合計

比較前にJSTタイムゾーン、立会時間、分割等の価格調整基準、当日未確定バーを揃える。許容差は日足と時間足の刻み・丸め仕様を実測して事前固定する。差が基準を超えた場合はその銘柄・日付の時間足を品質不合格にし、ログへ両系列・差分・原本ハッシュを保存する。日足から欠落した1時間足の時刻別OHLCを逆算して埋めない。

日足で代用できるのは、完了済み過去日の「日足」特徴量や5BDのentry/exit評価値まで。シグナル日の13時時点で、その後に形成される日足終値・高値・安値・出来高を使うと未来情報になる。5BDバックテストへ日足を用いる場合も、時間足シグナルの代替ラベルと混ぜず、日足だけのtarget/strategyとして明示する。今回の調査用worktreeには照合できる1時間足/4時間足データファイルが見つからなかったため、乖離率や閾値はまだ数値化していない。

## 欠損を過大計上しないための次のローカル監査

1. `MISSING_CANONICAL_LABEL`の行を特定し、既存の無視対象キャッシュ・保存済み日足・XTKSカレンダーだけで同じラベルを再生成できるか確認する。これはソース価格の補完ではなく、研究パイプラインのカバレッジ修復であり、追加データ取得なしに通常Pythonで実行可能。
2. 日付×銘柄ごとにエントリー始値、5営業日目終値、中間セッションOHLCVの有無を分離し、未解決理由を `MISSING_ENTRY_BAR` / `MISSING_EXIT_BAR` / `INTERMEDIATE_ONLY_GAP` / `ZERO_VOLUME_OR_UNACTIONABLE` / `LABEL_JOIN_MISSING` に分けて件数・偏りを報告する。
3. 端点が揃う中間日欠損では端点比を診断用に計算してもよいが、現行のフルセッション・アクショナビリティ基準の主成績へ混ぜない。比較する場合は「端点のみ診断」と明記し、全行を元のcanonical判定でも残す。
4. 独立した、利用条件を満たす無償ソースが確認できない間は、raw price補完をしない。ゼロ出来高・停止・上場状態不明を推測で取引可能扱いしない。
5. 選出要求数・解決数・未解決数/理由・年/月/銘柄別偏りを併記し、解決済み部分集合だけの成績が欠損偏りに左右されないか監査する。

研究は通常のローカルPythonだけで続行できるが、新規取得による補完は、無償かつ自動利用・Bot用途が許可されたデータソースが確認できるまで止める。日足から1h/4hを合成する案も実装しない。
