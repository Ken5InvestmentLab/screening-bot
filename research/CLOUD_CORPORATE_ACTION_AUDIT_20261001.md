# Cloud 株式分割・併合対策の検証

2026-10-01。実装コミット `9e5c363a`。研究ブランチ `research/weak-early-beta` に保存済み。

## 結果

Cloud の取得・検出・売買評価で価格と株数の基準を明示した。相対的なテクニカル特徴量は連続した調整済み系列、株価上限・最低出来高・売買価格は各営業日当時の単位で計算する。シグナル翌営業日に実100株を購入した原価を固定し、保有期間中の分割・併合を順に保有株数へ適用する。

1,000円以下は取得する銘柄数の制限ではなく、学習・検出対象の前営業日終値の条件である。TV-Free/V7研究から引き継がれた値で、1,000円が最適という根拠はコード・当時の研究記録から確認できなかった。価格上限の変更判断は、別途6群を再学習する同期間の研究結果による。

## 実装した契約

- Yahoo OHLCVの価格基準を宣言し、株式分割・併合のイベントを取得する。配当調整の `Adj Close` 比率は株式分割係数として使わない。
- イベント日の株価は変更後の単位、その前の株価は変更前の単位に復元する。価格がない日のイベントも保存し、架空の営業日・価格行を作らない。
- 不整合OHLC、修復後の価格・出来高の単位が曖昧な系列、極端な併合と長い価格欠落で同じ証券コードの同一性が確認できない系列は、原値と理由を保存して隔離する。特徴量入力では価格を無効化し、日付位置を残す。
- 古いキャッシュは「イベントなし」として処理しない。ソース更新前後の実単位価格を照合し、説明できない改訂は停止する。失敗した更新で既存キャッシュを上書きしない。
- エントリー・出口は日本の銀行営業日カレンダーで決める。予定日の価格が欠けても、次に価格がある日へずらさない。
- 保有中イベントは `entry_date < effective_date <= exit_date` のみ適用する。購入日の分割を重ねて適用しない。途中で端株が発生する場合は、現金精算額を推測して成績へ入れない。
- 検証済みの確定取引は価格・株数・原価・損益・イベント証跡を固定する。後日の分割や供給元の変更で上書きしない。
- 保存済みcanonical履歴は旧調整価格による参考値として明示し、通常の未確定行更新で置換しない。過去の円損益・必要資金を実100株へ復元できたと主張しない。
- 日次処理のソース監査は日足CSVのSHA-256と結び付け、品質監査・改訂検証の全証跡をsidecarに保存する。
